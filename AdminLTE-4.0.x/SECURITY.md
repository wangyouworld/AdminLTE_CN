## 安全最佳实践

AdminLTE 是一款前端管理仪表板模板。在部署使用 AdminLTE 构建的应用程序时，请遵循以下安全最佳实践：

### 1. 生产部署

- 在生产环境中**切勿公开 `node_modules` 目录**
- 从生产构建中移除演示/示例文件（例如 `index2.html`, `index3.html`）
- 使用仅包含必要生产资源的恰当构建流程
- 正确配置网络服务器，以防止目录遍历攻击

### 2. 构建过程

在部署到生产环境时：

```bash
# 仅构建生产环境所需资源
npm run production

# 只部署您所需的内容到 dist/ 目录中
# 通常情况下：dist/js/adminlte.min.js 和 dist/css/adminlte.min.css
```

### 3. 不宜部署的内容

请勿将以下内容部署到生产环境中：
- `node_modules/` 目录
- 示例/演示的 HTML 文件（如 `index.html`, `index2.html`, `index3.html` 等）
- 源文件（`src/` 目录）
- 开发配置文件
- 文档文件

## 已知的 CVE 问题

### CVE-2021-36471（存在争议）

**状态**：此 CVE 被认为**存在争议**，并且并不意味着 AdminLTE 系统本身存在漏洞。

**问题**：CVE-2021-36471 指出 AdminLTE 3.1.0 存在"目录遍历漏洞"，该漏洞使得远程攻击者能够通过访问 `/admin/index2.html` 和 `/admin/index3.html` 来查看演示页面。

**说明**：
- `index2.html` 和 `index3.html` 这两个文件是 **示例/演示页面**，旨在供开发人员在开发过程中参考
- 这并非 **AdminLTE 的漏洞** - 它是由网站开发者在部署时出现的 **配置错误**
- 问题出现在开发者错误地进行以下操作时：
  - 将其整个 `node_modules` 文件夹公开部署
  - 在生产环境中部署演示/示例文件
  - 且未进行适当的 Web 服务器配置

**决议**：
- AdminLTE 4.x 已对项目架构进行了重新设计，实现了开发演示与生产资源的清晰区分
- 请遵循上述的生产部署最佳实践
- 仅部署来自 `dist/js/` 和 `dist/css/` 目录的编译后的生产资源
- 该原始的漏洞研究员已确认，此漏洞应被归类为低/信息级别严重性，而非严重级别

**了解更多**：
- [GitHub 问题 #4948](https://github.com/ColorlibHQ/AdminLTE/issues/4948)
- [CVE 记录](https://www.cve.org/CVERecord?id=CVE-2021-36471) (标记为存在争议)

## 安全开发

### 内容安全策略（CSP）

在将 AdminLTE 应用到您的系统中时，请考虑添加适当的内容安全策略标头，以防止 XSS 攻击。

### 身份验证与授权

AdminLTE 仅是一个**用户界面模板**，不包含认证或授权功能。您需要：
- 在后端实现适当的认证机制
- 保护所有 API 端点
- 在生产环境中使用 HTTPS
- 实施适当的会话管理
- 遵循 OWASP 安全指南

### 依赖项

- 保持 AdminLTE 及其相关依赖项处于最新状态
- 定期运行 `npm audit` 以检查是否存在漏洞
- 查阅 Bootstrap 及其他依赖项的安全公告

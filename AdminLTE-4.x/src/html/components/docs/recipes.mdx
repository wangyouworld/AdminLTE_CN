##### 一个与真实语言环境联动的语言切换器

演示版的顶栏自带一个语言下拉菜单，但光有这点标记其实什么都变不了——切换语言区域是应用自己的活儿，而且做砸了还不如不做。下面这套模式涵盖了语言切换器真正必须做对的那些事。

```html
<li class="nav-item dropdown">
  <a class="nav-link" href="#" id="language-menu" data-bs-toggle="dropdown"
     aria-expanded="false" aria-label="Change language, current language English">
    <i class="bi bi-translate" aria-hidden="true"></i>
  </a>
  <ul class="dropdown-menu dropdown-menu-end" aria-labelledby="language-menu">
    <li>
      <a class="dropdown-item active" href="/en/dashboard" hreflang="en" aria-current="true">
        English <i class="bi bi-check-lg ms-2" aria-hidden="true"></i>
      </a>
    </li>
    <li><a class="dropdown-item" href="/es/dashboard" hreflang="es">Español</a></li>
    <li><a class="dropdown-item" href="/ar/dashboard" hreflang="ar">العربية</a></li>
  </ul>
</li>
```

四件事决定了语言切换器是真能用还是纯摆设：

1. **每一项都是一个真正的链接，指向同一页面在另一种语言区域下的版本**，而不是一个带点击事件的 `#`。链接可以被收藏、被爬虫抓取、能新标签页打开，而且在你的 JavaScript 加载之前就能用。再加上 `hreflang`，这样辅助技术能播报语言变化，搜索引擎也能把对应的 URL 配对起来。
2. **语言区域应该放在 URL 里**（比如 `/es/dashboard`），或者放在服务器能读取的 cookie 里——而不是放在 `localStorage` 里。服务端渲染的 HTML 必须在渲染*之前*就知道语言区域是什么，而 `localStorage` 要等页面已经以错误语言发出去了之后才能读到。
3. **标记当前语言**，同时用上 `.active` 和 `aria-current="true"`，并在切换按钮的 `aria-label` 里写明当前语言。光有一个国旗图标并不能代表一门语言：好几种语言共用一个国旗，也有好几个国家共用一门语言。
4. **切换到 RTL（从右到左）语言区域时，需要配套的 RTL 样式表**，光加个 `dir` 属性是不够的。要同时提供 `adminlte.rtl.css` 并设置 `<html lang="ar" dir="rtl">`——详见 [RTL 支持](rtl.html)。

如果你的语言区域放在 URL 里，那么由服务器来挑样式表，切换器本身就可以保持纯标记：

```html
<!-- 按请求、基于当前激活的语言区域实时渲染 -->
<html lang="ar" dir="rtl">
  <link rel="stylesheet" href="/css/adminlte.rtl.css">
```

对于客户端渲染的应用，要在路由层面做同样的事——切换语言区域、重新渲染、替换样式表的 `href`——而不是就地去翻译文本节点。

##### 响应布局/侧边栏变更

监听插件事件，好跟你自己的代码配合 —— 比如侧边栏收起时让某个组件重新适配（这样它就会重新测量容器的宽度）：

```js
let table = /* your Tabulator instance */

document.addEventListener("collapse.lte.push-menu", () => {
  // wait for the transition to finish (~300ms by default)
  setTimeout(() => table.redraw(), 350)
})

document.addEventListener("open.lte.push-menu", () => {
  setTimeout(() => table.redraw(), 350)
})
```

同样的套路也适用于 FullCalendar（`calendar.updateSize()`）以及任何其他在初始化时读取容器宽度的库。Chart.js 的图表在这里什么都不用做：它们用 `ResizeObserver` 监视自己的容器，会自动重绘。

##### 会跟随深色模式的图表

图表库是基于画布绘制的，因此它们对 `data-bs-theme` 或其他 CSS 一无所知：Chart.js 会使用其自身固定的默认颜色来绘制坐标轴标签、网格线和数据工具提示，这些颜色适合浅色页面，但在深色卡片上几乎完全不可见。你需要手动为它提供颜色，并在模式更改时再次传递这些颜色。

绘制图表的演示页面都带了一个小预设（`src/html/components/_chartjs.astro`，在每个页面上内联在 Chart.js 之后）。它把 AdminLTE 的 CSS 变量读进 `Chart.defaults` —— 字体族、文字颜色、网格线、跟界面其余部分风格一致的提示框和图例，以及在 `<html dir="rtl">` 时的 `rtl` 设置 —— 并监听 `<html>`，这样页面上的每张图表都会在模式变化时重新刷样式，不管变化是来自切换器、auto 模式下的系统偏好，还是你自己的代码。它的核心部分：

```html
<script src="https://cdn.jsdelivr.net/npm/chart.js@4.5.1/dist/chart.umd.min.js"></script>
<script>
  const root = document.documentElement
  const cssVar = (name) => getComputedStyle(root).getPropertyValue(name).trim()

  const applyTheme = () => {
    const grid = `rgba(${cssVar("--bs-emphasis-color-rgb")}, 0.08)`
    Chart.defaults.font.family = cssVar("--bs-body-font-family")
    Chart.defaults.color = cssVar("--bs-secondary-color")        // 标记与标题
    Chart.defaults.borderColor = grid                            // 网格线和坐标轴线
    Chart.defaults.plugins.legend.labels.color = cssVar("--bs-body-color")
    Object.assign(Chart.defaults.plugins.tooltip, {
      backgroundColor: cssVar("--bs-body-bg"),
      borderColor: cssVar("--bs-border-color"),
      borderWidth: 1,
      titleColor: cssVar("--bs-emphasis-color"),
      bodyColor: cssVar("--bs-body-color")
    })
    Chart.defaults.elements.arc.borderColor = cssVar("--bs-body-bg") // 甜甜圈切片间隙
  }

  applyTheme()
  new MutationObserver(() => {
    applyTheme()
    for (const chart of Object.values(Chart.instances)) chart.update("none")
  }).observe(root, { attributes: true, attributeFilter: ["data-bs-theme"] })
</script>
```

在这个脚本之后创建的图表会默认采用这些颜色，而 `chart.update()` 会让已有的图表重新读一遍。你在数据集上自己设的颜色（`borderColor: "#0d6efd"`）归你自己所有，会保持原样；而需要跟随模式变化的颜色可以写成一个函数，Chart.js 会在每次更新时重新调用它 —— `backgroundColor: () => cssVar("--bs-secondary-bg")`。

如果你更想用 ColorMode 事件，而不是监听属性变化，可以用 `document.addEventListener("changed.lte.color-mode", e => …)`，它会收到 `e.detail.resolved`（值为 `"light"` 或 `"dark"`）；而上面那个监听器还额外覆盖了 auto 模式下的系统偏好变化，以及任何直接设置这个属性的代码。同样的思路也适用于其他图表库：找到它们从哪里取文字、网格和提示框的颜色，把 CSS 变量喂给它们，然后在变化时重新应用一遍。

##### 将页面作为文档打印

打印页面是一种文档，而非应用程序的截图，因此 AdminLTE 会将页面的外壳（页眉、侧边栏菜单和页脚）省略在纸上，而让内容占据整张纸的宽度。打印时的样式是为纸质阅读而设计的：外部链接的目标文本会被打印在后面，按钮保持轮廓以确保仍能识别为按钮，所有内容都采用黑白配色，避免背景遮盖墨迹。

对于那些要打印成*文档*的页面 —— 比如发给客户的发票、报价单、工单或装箱单 —— 最后那两样就是错误的输出：没人希望打印出来的发票上带着 `在线支付 (https://pay.example.com/inv/12345?token=…)`，也没人希望按钮外面被画上一个框。把 `data-lte-print="plain"` 加在 `<html>`、`<body>` 或任意容器上，这两样就都没了，同时文字保持白底黑字：

```html
<html lang="en" data-lte-print="plain">
```

当页面中仅有部分内容需要作为文档打印时，可将打印作用域限定到该部分：

```html
<div class="card" data-lte-print="plain">……发票……</div>
```

如果页面仅以文档形式打印，请在打印时设置该属性：

```js
document.querySelector("#print-invoice").addEventListener("click", () => {
  document.documentElement.setAttribute("data-lte-print", "plain")
  window.print()
})
```

反过来 —— 如果某个页面确实就是要按屏幕内容打印，连菜单一起 —— 在 `<html>` 或 `<body>` 上加 `data-lte-print="app"`，就会把整个外壳都打印出来：

```html
<html lang="en" data-lte-print="app">
```

如果想恢复其中某一块而不是全部三块，就用 Bootstrap 自带的显示工具类。头部（它是个 navbar）适合用 `.d-print-flex`，侧边栏和页脚则用 `.d-print-block`：

```html
<aside class="app-sidebar bg-body-secondary shadow d-print-block" data-bs-theme="dark">…</aside>
```

`.d-print-none` 在两种模式下都能隐藏任何你不想印在纸上的东西 —— 比如发票上方那一排按钮工具栏。
